Packaging the Catalog API: what actually moved the needle

Twelve ways to hand the same media catalog to the same model. The winner is not the richest tool set — it is a code sandbox plus a short, hand-written skill that teaches the hierarchy, the dangerous writes, and when to refuse.

gpt-5.6-luna · reasoning low 58 tasks · 2 repeats · hard 1,312 runs · Aug 6, 2026

Ship D2-auth — code sandbox + authored skill

84% success · 100% correct refusals · 0 data clobbers · about half the tokens of bare MCP.

On accuracy alone it ties the next-best packaging (D1, 78%) — that 6 pp gap is below this run’s 23 pp detection floor. It wins the composite because it never invents answers on unanswerable tasks and never destroys fields with a careless replace_episode.

Three jobs, three picks

Same model, different packaging. Choose by what you optimise for — not by the composite score alone.

When you must not be wrong

D2-auth — precision over everything

100% precision 100% abstention 0 false answers 0 clobbers 84% success

Money and latency do not matter here. Among packaging arms, only D2-auth is perfect on both axes that measure “making something up”: it never invents an answer when the catalog cannot provide one, and it never wipes a title or runtime with replace_episode. B1-auth and B2-auth also hit 100% precision, but both still clobbered data (6 and 1 times). If the cost of a wrong write is catastrophic, this is the one you’d ship.

When wall-clock is the constraint

B1 — fastest packaging

15.3 s mean 67% success 3 false positives 2 clobbers

Eager-all MCP with a generated skill finishes first — about 11 s faster than D2-auth. Schemas are already in context, so there is no discovery tax and almost no sandbox setup.

You pay for that speed: lower accuracy, occasional fabricated answers, and real write damage. If you need fast and careful, B1-auth is only ~1 s slower (16.4 s) with perfect abstention — but still clobbers.

Four findings that matter

Everything else in the full report is detail. These four explain the ranking.

1. The authored skill’s real gift is knowing when not to answer

Swapping a generated skill for the hand-written Catalog skill lifts success a modest +7 to +10 pp. Abstention on unanswerable tasks jumps far more: B1 44% → 94%, D2 56% → 100%. The skill’s last section — “say it cannot be determined rather than offering the closest match” — is doing more work than the hop-by-hop lookup tips.

2. Discovery meta-tools tax the turn budget before work begins

Arms that must search → describe → invoke (A2, B2, B2-auth) truncate on 18–29% of runs. Eager-all MCP truncates ~5%; code and bash arms truncate 0%. Discovery is not free exploration — it spends the same turn budget the task needs, so many “failures” never get a chance to be wrong.

3. Harm has a fingerprint: PUT wiped the object

Almost every clobber zeroes title or runtime_seconds — the signature of replace_episode instead of patch_episode. The Catalog skill warns about this explicitly. Code-sandbox arms nearly eliminate it (D2-auth: zero harm). Full-tool MCP still does it even with the authored skill (B1-auth: 6 clobbers) — having the dangerous tool in the schema outweighs the prose warning.

4. Intermediate results in a sandbox beat more tools in context

Successful D2-auth runs use ~6k peak context tokens and ~5 calls. Bare MCP (A1) needs ~14k tokens and ~11 calls for worse accuracy. Keeping state in code, not in the chat, is the efficiency story — not “more documentation.”

Where D2-auth still fails

Nineteen misses out of 116 — none of them refusals-gone-wrong or clobbers. The residual is execution, not packaging philosophy.

  • 5

    Missed archive

    Irreversible write never applied — scope caution without a dry-run follow-through.

  • 4

    Rating / status patch wrong or skipped

    Safe writes that should be a single patch_episode.

  • 4

    Wrong read answer

    Hierarchy walk completed; the extracted value was off (e.g. year).

  • 2

    Incomplete fan-out tags

    Tagged some episodes in a season, not all — the skill’s “no bulk endpoint” path.

Do not read B1-auth as “almost as good.” It scores 75% with perfect abstention, but still clobbered six episodes via replace. For a catalog that must not lose titles and runtimes, that is a different product risk than D2-auth’s nineteen clean misses.

What to take away

  1. For “don’t make a mistake,” ship D2-auth. Perfect precision, perfect abstention, zero clobbers — the only packaging that wins every safety axis at once.
  2. Speed and cheapness point elsewhere, with caveats. B1 is fastest; B1-auth is cheapest per success. Both still harm data when replace is in the tool schema.
  3. Invest in an authored skill that teaches refusal and dangerous writes, not a generated dump of every endpoint. Abstention is where the authored skill pays off.
  4. If you must expose write tools eagerly, hide or rename replace_*. Prose warnings do not reliably override a tempting PUT in the schema.
